# 二分查找 · 五亿数据 29 步锁定目标

同系列竖屏数学动画第九篇：把二分查找"每步砍一半"的过程可视化。五亿条有序数据中查找目标 314159265（π 前 9 位），恰好 29 步命中，对应 `⌈log₂(5×10⁸)⌉ = 29`。

## 画面结构

- **双语标题**（顶部）：中文「二分查找」+ 英文「BINARY SEARCH」，右下角 `AIMaker-Lab` 小水印；中文由 `cn_text()` 用微软雅黑预渲染（衬线字体缺中文字形）
- **GLOBAL 全局数据带**：`1 … 500,000,000`，格线画成"一格一格的有序数组"；青色 = 当前候选区间，红竖线+下三角 = 中点 `mid`，橙竖线+上三角 = 目标 `T`（指针方向相反便于区分）
- **ZOOM 放大带**：当前候选区间拉伸铺满；每步把即将丢弃的一半画成**红色斜纹**，青色保留区相应收缩，"砍半"看得见
- **决策文字**（中文）：`A[mid] < T → 目标在右，丢掉左半` / `A[mid] > T → 目标在左，丢掉右半` / `A[mid] = T → 找到了！`
- **收缩曲线**（左下）：对数轴上剩余候选量从 5 亿指数下降到 1，红点沿曲线右移
- **数值行**（两行）：`step`（比较次数）、`remain`（剩余候选）在上；`mid`（当前中点）、`T`（目标）在下
- **底部公式链**：有序前提 → 中点公式 → 左右两支更新 → 步数上界

约 16.15s 处循环重置（标题闪烁 + 数据带/曲线归位）。

## 数学主线

```
前提:   A[0] ≤ A[1] ≤ … ≤ A[n−1]              (必须有序)
中点:   mid = ⌊(lo + hi) / 2⌋
A[mid] < T  ⇒  lo ← mid + 1                   (去右半)
A[mid] > T  ⇒  hi ← mid − 1                   (去左半)
步数:   steps ≤ ⌈log₂ n⌉ = 29  (n = 5×10⁸)
```

规模每翻一倍，二分只多半步：`log₂(5×10⁸) ≈ 28.9`。而线性查找平均需 `n/2 = 2.5 亿` 次，相差约 1700 万倍。

## 文件

| 文件 | 说明 |
|------|------|
| `binary_search_scene.py` | 自包含 Manim 场景：预演算 29 步事件链 + `apply(t)` 查表；`DataStrip` 用 numpy 位图整块映射并原地更新 `pixel_array`；公式 mathtext 预渲染 PNG，动态数字 `PixelNumber` 纯内存刷新。 |
| `add_bgm.py` | 合成专属配乐 **BISECT / C-Lydian** 并混入成片：方波 PWM pad + 玻璃谐波铃 + 高通噪声 ticks + 11/8 拍 + 递减间隔收缩音序，全程不循环；自带与库内旧片的波形相似度检验（要求 < 0.1）和自身无循环检验（自相关 < 0.8）。 |
| `precheck.py` | 离线校验全部公式的 mathtext 可渲染性。 |
| `formulas/` | 9 个公式 PNG 缓存（不存在时脚本会自动生成）。 |

## 复现

```bash
pip install -r ../../requirements.txt
manim -pqh binary_search_scene.py BinarySearch          # 1080×1350 / 30fps / 22.33s
python add_bgm.py <渲染出的视频> binary_search_final.mp4
```

全程**无需 LaTeX**；脚本使用相对路径，克隆后可直接运行。
